⚙️ Request Execution Pipeline & Concurrency Architecture

Every incoming TCP connection flows through a strictly decoupled single-pass byte buffer parser and routing engine before generating framed HTTP response headers.

STAGE 1

TCP Listener Loop

Binds socket.AF_INET TCP socket with SO_REUSEADDR and non-blocking accept handling.

➔
STAGE 2

Thread Dispatch

Spawns standard threading.Thread worker for isolated socket I/O lifecycle with 5s timeout enforcement.

➔
STAGE 3

Byte Buffer Parser

Streams raw socket chunks until double CRLF (\r\n\r\n) boundary to extract headers & payload body.

➔
STAGE 4

Regex Parametric Router

Matches request path against registered regex patterns to extract dynamic URI path variables (<id>).

➔
STAGE 5

Framing & Response

Applies RFC 7231 headers, resolves MIME types via mimetypes, and writes bytes back to client socket.

🛡️ Path Traversal Defense

Sanitizes requested URIs by resolving canonical paths using pathlib.Path.resolve(). Any path attempting to break out of the static root directory returns an immediate 403 Forbidden response.

GET /../../../../etc/passwd ➔ 403 Forbidden
⏱️ Socket Resource Guards

Enforces 5.0s timeouts on client sockets to prevent Slowloris resource exhaustion attacks. Implements explicit maximum header buffer thresholds (8192 bytes) to defend against memory exhaustion.

MAX_HEADER_SIZE = 8192 | client_sock.settimeout(5.0)
